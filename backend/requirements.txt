# The <0.136 cap is lifted here (#265). It was never a real incompatibility.
#
# The 2026-06-14 note claimed fastapi 0.136.x "silently registers ZERO routes"
# against our starlette. Measured 2026-07-28 on the exact pair it named —
# fastapi 0.136.3 with starlette 0.49.3, unchanged:
#   len(app.routes) 626 · count_routes 626 · full backend suite 3081 passed
# And on the current latest, fastapi 0.140.7, same starlette:
#   len(app.routes) 145 · count_routes 626 · full backend suite 3081 passed
#
# That 145 is the whole story. From somewhere in 0.137-0.140, included routers
# stay behind a wrapper instead of being flattened, so len(app.routes) stopped
# being an endpoint count. Nothing was ever lost — the *measurement* broke, and
# a small number got read as mass route loss. Use
# backend.route_introspection.count_routes, never len(app.routes).
#
# The starlette "lockstep bump" the old note demanded is also unnecessary:
# fastapi 0.136+ requires starlette>=0.46.0, which 0.49.x already satisfies.
# starlette stays where it is; this is a one-sided bump.
#
# Guarding it: backend/tests/test_router_composition_semantics.py pins
# middleware ordering, include_router dependencies=, prefix composition, and
# mounted sub-apps; test_route_introspection.py asserts the real app still
# registers >500 routes on any version. Keep the upper bound so a future major
# lands deliberately rather than silently.
