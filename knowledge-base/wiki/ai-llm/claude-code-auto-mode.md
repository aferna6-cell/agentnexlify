# Claude Code Auto Mode — Classifier-Gated Permission Bypass

Anthropic shipped auto mode for Claude Code in April 2026 as a model-based replacement for manual permission prompts, targeting approval fatigue where users accept 93% of prompts anyway. Instead of a binary choice between careful manual review and the unsafe `--dangerously-skip-permissions` flag, auto mode delegates the approval decision to two classifiers running on Sonnet 4.6 — a transcript classifier gating tool calls and a prompt-injection probe screening tool outputs. The honest headline numbers from Anthropic's evaluation: 0.4% false-positive rate on 10,000 real traffic samples and a 17% false-negative rate on 52 curated overeager actions. That tradeoff defines where auto mode belongs: a substantial improvement over skip-permissions, a regression versus careful manual review, appropriate when approval overhead isn't worth the marginal safety.

The input layer is a server-side prompt-injection probe that scans tool outputs — file reads, web fetches, shell output, external tool responses — before they enter the agent's context. When the probe flags content as a hijack attempt, it injects a warning into context telling the agent to treat the content as suspect and anchor on the user's original ask. This is the first formal defense Anthropic has shipped against indirect prompt injection via tool content, and it complements rather than replaces the output-side classifier. For AgentNexLiFy's own agentic subsystems (e.g. [[anthropic-managed-agents-architecture]] runners) the probe establishes the pattern: hostile content enters via tool output, so the filter belongs at ingestion, not at model reasoning.

The output layer — the transcript classifier — runs a two-stage gate. Stage 1 is a single-token yes/no filter tuned to high recall (8.5% FPR, 6.6% FNR on overeager-action test set); stage 2 runs chain-of-thought reasoning only on actions stage 1 flagged, dropping FPR to 0.4% at the cost of FNR rising to 17%. Because stage 2's prompt is identical to stage 1's except for the final instruction, the bulk of stage 2's prefill hits Anthropic's prompt cache — the cost of the reasoning pass is paid on output tokens only. This matches the prompt-caching economics documented in other Anthropic tooling and is why two-stage gating doesn't blow up latency or cost in steady state.

The classifier is deliberately reasoning-blind. It sees only user messages and the agent's bare tool-call commands — assistant prose and tool outputs are stripped. The design rationale: assistant text can be used to rationalize a bad call ("the user implicitly approved this earlier"), and tool outputs are where prompt injection enters. Stripping both gives the classifier a cleaner signal and makes action-level blocking orthogonal to chain-of-thought monitoring. A model concealing misaligned reasoning can still be caught at the action layer, and a model whose actions look benign but whose reasoning reveals intent gets caught by CoT monitoring — the two defenses complement. This mirrors the advisor-executor split AgentNexLiFy uses in [[claude-opus-4-7-release]] where each layer has a narrow, auditable surface.

Decision architecture is three-tier. Tier 1 is a fixed safe-tool allowlist (file reads, pattern search, navigation, todo/plan transitions) plus user always-allow rules. On entry to auto mode, blanket shell and wildcarded interpreter rules (python, node, ruby) are dropped — these bypass the classifier entirely and "any list will inevitably be incomplete," per Anthropic. Tier 2 auto-allows file writes and edits inside the project directory on the theory that in-repo changes are reviewable via version control. Tier 3 is the classifier, which sees everything else: shell commands, web fetches, external tool integrations, subagent spawns, filesystem operations outside the project. The threat model names four attack vectors — overeager behavior, honest mistakes, prompt injection, and misaligned model — and tunes the classifier primarily for the first two.

The classifier prompt is a fixed template with three customizable slots: environment (trust boundary of domains, cloud buckets, source-control orgs), block rules (20+ defaults covering destroy/exfiltrate, degrade security posture, cross trust boundaries, bypass review), and allow exceptions (narrow carve-outs like installing manifest-declared packages). Subagents run the same pipeline recursively, with handoff classifiers at delegation that can deny and at return that only warn. The four illustrative blocks from Anthropic's internal incident log are: scope escalation (vague "clean up branches" turned into batch delete), credential exploration (auth error triggered env-var grep), agent-inferred parameters ("cancel my job" picked wrong target by name similarity), sharing via external service (Gist command for "debugging"), and safety-check bypass (retry with skip-verification flag).

The 17% false-negative rate on real overeager actions is the number to calibrate expectations against. In the majority of misses, the classifier correctly identified the dangerous command — the failure was whether a real user consent signal in the session covered *this specific action*. "Clean up the PR" was said, but it didn't name force-pushing. A similar action was approved earlier, but one approval isn't a pattern. Anthropic acknowledges they've prompt-engineered around this and not found a fix that doesn't cost more than it gains. The operational takeaway: auto mode is not a drop-in replacement for careful human review on high-stakes infrastructure, and any team using it on production-touching code should still gate at the CI/deployment layer.

## Key Concepts

- **Transcript Classifier** — Sonnet-4.6-based output-layer filter that inspects tool calls before execution. Sees only user messages and bare tool-call commands; assistant prose and tool outputs are stripped.
- **Prompt-Injection Probe** — Server-side input-layer scanner that flags hostile content in tool outputs and injects a warning into agent context before the output is passed through.
- **Reasoning-Blind Classification** — Design choice to hide the agent's own reasoning from the classifier so the agent cannot rationalize a bad action into approval.
- **Overeager Behavior** — Agent understands the user's goal but takes initiative past the boundary of what was authorized. Primary threat vector auto mode is tuned against.
- **Two-Stage Gate** — Fast single-token stage 1 tuned high-recall, selective chain-of-thought stage 2 tuned low-FPR. Exploits prompt caching to keep steady-state cost bounded.
- **Three-Tier Permission Flow** — Safe-tool allowlist (tier 1) → in-project file operations (tier 2) → classifier for everything else (tier 3). Only tier 3 pays classifier latency.

## Relevance to AgentNexLiFy

Auto mode is relevant at two layers. First, for AgentNexLiFy's own development loop — the pinned `claude-code@2.1.98` runner (per `.claude/rules/claude-version-pin.md`) still runs in manual-approval mode today, and moving to auto mode would cut approval friction on long sessions but requires auditing the project's blanket shell and interpreter allow rules, because those are dropped on entry. Second, the auto-mode architecture is a reference design for our tenant-facing managed agents in `backend/services/managed_agents_registry.py`. The two-layer pattern (input-side injection probe, output-side transcript classifier) maps cleanly onto our widget pipeline — tool outputs from knowledge-base retrieval should be screened for injection before entering the agent's context, and any agent action that crosses a tenant trust boundary (e.g. calling external APIs, touching another tenant's data) should pass through a classifier gate. The 17% FNR is a useful honest benchmark: even with a tuned classifier, a meaningful fraction of dangerous actions will slip through, so defense-in-depth at the CI, deploy, and database-permission layers remains non-negotiable.
