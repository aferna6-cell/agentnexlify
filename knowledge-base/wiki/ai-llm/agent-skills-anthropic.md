# Agent Skills — Anthropic's Progressive-Disclosure Capability Format

Agent Skills formalize how Claude and other agents acquire domain-specific capabilities without stuffing every possible instruction into the system prompt. A skill is simply a directory containing a `SKILL.md` file with YAML frontmatter (required fields: `name`, `description`) plus any optional supporting files — markdown references, Python or shell scripts, images, datasets. At agent startup, only the `name` and `description` of each installed skill pre-load into the system prompt, so hundreds of skills can coexist while the main context window stays lean. Skills were published as an open standard at agentskills.io in December 2025 for cross-platform portability, and are now supported across Claude.ai, Claude Code, the Claude Agent SDK, and the Claude Developer Platform.

Progressive disclosure is the core design principle that makes skills scale. The format has three tiers of detail. Tier one — name and description — is always in context; this is the decision layer where Claude judges whether a skill is relevant to the current task. Tier two — the body of SKILL.md — loads only when Claude decides to use the skill, typically by reading the file via Bash or the file-read tool. Tier three — bundled supporting files — loads only when SKILL.md references them and Claude follows the reference. A well-designed skill keeps the core SKILL.md lean by splitting mutually-exclusive or rarely-needed content into separate files. The PDF skill that powers Claude's document editing, for example, keeps form-filling instructions in a separate `forms.md` that loads only when Claude is filling out a form, not every time a PDF is opened. The practical ceiling: since additional tiers load on demand, the total context a skill can package is effectively unbounded.

Skills also support executable code as first-class content. The PDF skill bundles a Python script that reads PDFs and extracts form fields — Claude runs the script via its Bash or code-execution tool without loading either the script source or the raw PDF into context. This matters for two reasons. First, deterministic operations (sorting, parsing, schema validation, data extraction) are orders of magnitude cheaper as code than as token generation. Second, code is repeatable and reliable in ways LLM reasoning over the same operation often isn't. The clear rule: it should be obvious from the skill whether a given script is meant to be executed as a tool or read into context as reference documentation.

Development guidance follows four principles. Start with evaluation — identify gaps by running agents on representative tasks and observing where they struggle, then build skills incrementally to fill those gaps rather than speculatively. Structure for scale — split SKILL.md when it becomes unwieldy, keep mutually-exclusive paths in separate files, be explicit about whether code is a tool or a reference. Think from Claude's perspective — monitor how the agent actually uses the skill, iterate based on real usage patterns, pay particular attention to `name` and `description` since they drive the trigger decision. Iterate with Claude — as you work through a task, have Claude capture successful approaches and common mistakes into reusable skill context; when a skill goes off track, ask Claude to self-reflect on what went wrong. This co-authoring pattern produces skills that encode what the agent actually needs, not what a human guesses it needs.

The security consideration is real and underplayed elsewhere. Skills give agents new capabilities via both instructions and code, which means a malicious skill can introduce vulnerabilities or direct the agent to exfiltrate data. Anthropic's guidance: install skills only from trusted sources, and when installing from a less-trusted source, audit the full skill directory before use — read all bundled files, examine code dependencies and bundled resources, watch for instructions or code that connect to external untrusted network sources. This matches the supply-chain concern Trail of Bits raised in their Claude Code security skills ([[claude-code-security.md]] in our rules), and is why AgentNexLiFy's CLAUDE.md lists only project-scoped skills plus explicitly-trusted Trail of Bits skills.

The future direction Anthropic flags is compositional: skills complementing MCP servers rather than competing with them (MCP gives external tool access, skills teach workflows that use those tools), and eventually agents creating, editing, and evaluating their own skills — codifying their own successful patterns into reusable capabilities. This closes the loop on the iteration principle: an agent that notices it's solving a similar problem repeatedly can package the solution as a skill for its future self or for other agents. For AgentNexLiFy, this is the pattern our `.claude/skills/` directory already uses — 50+ skills encode domain patterns (widget testing, schema guards, compound engineering, KB ingest/compile/query) that would otherwise require re-deriving from first principles every session.

## Key Concepts

- **SKILL.md** — The entry file of every skill. Starts with YAML frontmatter containing required `name` and `description`. Body contains the core instructions plus references to any bundled files.
- **Progressive disclosure** — Three-tier loading: frontmatter metadata always in system prompt, SKILL.md body loaded when skill is triggered, bundled files loaded only when referenced. Lets unbounded context ship with a minimal prompt footprint.
- **Skill directory** — Folder containing SKILL.md plus optional bundled files (markdown references, Python/shell scripts, images, datasets). Directory is the unit of distribution.
- **Bundled supporting files** — Additional files within a skill directory referenced by name from SKILL.md. Used for mutually-exclusive content, rarely-needed detail, or deterministic code scripts.
- **Executable skill content** — Scripts bundled in a skill that Claude runs as tools rather than reading into context. Favored for deterministic operations (parsing, sorting, schema validation) where token-generation equivalents are wasteful.
- **agentskills.io open standard** — Anthropic's December 2025 publication of the skill format as a cross-platform standard, enabling skills built for Claude to work across other agent runtimes.

## Relevance to AgentNexLiFy

AgentNexLiFy already runs on Agent Skills — `.claude/skills/` contains 50+ skills covering compound engineering, widget testing, KB ingest/compile/query, industry content, e2e testing, and deploy workflow. The article's guidance directly validates choices we've made (start from real gaps not speculation, keep SKILL.md lean with references to supporting files, treat `name` and `description` as trigger-decision primary surface). Three specific action items follow. First, audit our existing skills against the progressive-disclosure structure — if any SKILL.md is over ~150 lines with embedded reference material that could live in a `references/` folder, split it (this is already the documented pattern in `.claude/skills/wiki/references/template.md` so extending it to more skills is mechanical). Second, the co-authoring iteration pattern should become the default workflow for new skills: have Claude produce the first draft of SKILL.md based on observed successful patterns in a session, then edit down. Third, the security audit discipline applies — our project CLAUDE.md rules/plugins.md lists which plugin skills we trust; any third-party skill (including from new plugins) needs the same read-all-files, check-dependencies, watch-for-external-calls audit before install. Adopting the agentskills.io standard format for our own skills (if we don't already) makes them portable if we ever want to run parts of AgentNexLiFy on non-Anthropic agent runtimes.
