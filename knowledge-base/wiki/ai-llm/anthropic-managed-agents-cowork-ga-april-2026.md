# Anthropic April 9 2026 Triple Launch — Managed Agents Beta, Cowork GA, Claude Code Update

Anthropic shipped three coordinated updates on April 9, 2026: Claude Managed Agents entered public beta with composable APIs, sandboxes, and a credential vault; Claude Cowork went from research preview to general availability with six enterprise features; and Claude Code received a policy-controls update with a Bedrock setup wizard. Pasquale Pillitteri's April 11 follow-up adds the pricing details Anthropic clarified three days post-launch and identifies the credential vault as the load-bearing security primitive most coverage missed. The bundle is best read as Anthropic's response to OpenAI's April 9 investor memo on compute-scale advantage — Anthropic is choosing developer-ecosystem differentiation over compute-quantity messaging, and the operational implications for AgentNexLiFy's [[anthropic-managed-agents-architecture]] dependency are direct.

Managed Agents is now generally accessible on the Claude Platform without invitation. The three-day-post-launch pricing clarification matters: standard token cost stays at Sonnet 4.6 $3/$15 and Opus 4.6 $5/$25 per million input/output, but active session runtime is now billed at $0.08/hour metered in milliseconds — idle agents do not accrue charges. Integrated web search costs $10 per 1,000 searches via the native tool. The two officially documented endpoints are `POST /v1/agents` to register a persistent agent with system prompt, tools, and permissions, and `POST /v1/sessions` to start an execution session. The Python SDK exposes both through `ClaudeSDKClient` as an async context manager. For cron-style automation that runs short bursts every 15-30 minutes, the active-session billing is materially cheaper than naive container-runtime billing — an agent doing 60 seconds of work hourly costs $0.0013/hr in runtime, dwarfed by the underlying token bill. This pairs naturally with the cache-architecture math captured in [[claude-prompt-caching-5min-ttl-2026]], where keepalive design now governs a larger share of the all-in cost.

The credential vault is the under-discussed primitive. Managed Agents stores secrets encrypted and surfaces them to the agent at runtime without exposing them in code or logs, and supports native OAuth flows for ClickUp, Slack, and Notion with automatic token refresh. Custom tools accept OAuth tokens stored via MCP. This eliminates the "secrets in environment variables" anti-pattern that plagues self-hosted agent harnesses and removes one of the largest classes of security incident from the threat surface. For tenant-facing agent products, it also resolves the tenant-isolation question — each managed agent session runs in a dedicated container with permission scoping enforced by Anthropic's runtime, not by the application code that called it.

Claude Cowork's GA introduces six enterprise-tier features. RBAC lets admins configure access by team and department on the Enterprise plan. Group Spend Limits cap user-group spend for budget control on Enterprise. Expanded Usage Analytics surface dashboards on cost and interaction patterns on Team and Enterprise. OpenTelemetry support is the most operationally consequential — native OTLP integration means Datadog, Grafana, New Relic, and Honeycomb all work without custom shims, available on Enterprise. Zoom MCP Connector ships across all paid plans for meetings and transcriptions. Per-Tool Connector Controls give security admins granular per-user control on Team and Enterprise. The release pattern matches the "platform expansion" thesis already documented in [[anthropic-claude-release-notes-feb-apr-2026]], where Cowork has steadily picked up enterprise-administration features in advance of Anthropic's enterprise sales push.

Claude Code's policy controls represent the most-requested enterprise feature, finally shipped. Admins can now define granular rules on which shell commands Claude can execute, which files it can read or modify, which MCP tools are authorized, and rate limits for expensive operations. The Amazon Bedrock setup wizard collapses what was historically a multi-step credential and region-selection process into an interactive `claude bedrock setup` command — relevant for compliance- or data-residency-bound deployments. The `/cost` command now breaks down per task type, input vs output tokens, model comparison within a session, and a monthly projection. Large-file write performance improved 40-60% on files over 10k lines through new buffering and disk batching. Advanced prompt-cache hooks reduce token waste on consecutive calls, dovetailing with the caching architecture work in [[claude-prompt-caching-5min-ttl-2026]] and [[claude-code-april-23-postmortem-2026]].

The early-adopter list — Notion, Asana, Sentry — is strategic signal. Notion's most plausible use is workspace AI for document generation, page automation, and database analysis. Asana's is task planning, smart assignment, and project summaries. Sentry's is automatic stack-trace analysis, bug diagnosis, and incident prioritization. These three companies represent three distinct surface areas (knowledge management, project management, observability) and validate that Managed Agents serves both consumer-facing and infrastructure-facing agent workloads. Sentry's Seer agent (already documented in our integration tooling) likely runs on Managed Agents now, which means our Sentry MCP usage indirectly depends on Managed Agents reliability.

The competitive context is essential to read correctly. OpenAI's April 9 investor memo claims 30 gigawatts of compute by 2030 against Anthropic's 7-8 gigawatts by end of 2027. Anthropic's response is not to match the compute-scale narrative but to ship product-layer differentiation: managed runtime, enterprise observability, ad-free positioning ([[claude-ad-free-incentive-design-2026]]), and developer-ecosystem depth (Claude Code, Cowork, Managed Agents, Mythos). The strategic bet is that enterprise buyers care about ecosystem maturity and predictable security primitives more than raw compute headroom. For AgentNexLiFy, this is the right bet — our SMB tenants do not feel the compute-scale ceiling, but they do feel agent-runtime reliability when a widget conversation hangs.

## Key Concepts

- **Active session billing** — $0.08/hour metered in milliseconds for the time a Managed Agent is actually executing. Idle agents accrue zero runtime charge, making this billing model favorable for sparse cron-style workloads versus traditional container-runtime billing.
- **Credential vault** — Encrypted secret store inside Managed Agents that exposes credentials to the agent at runtime without surfacing them to code or logs. Native OAuth flows for ClickUp, Slack, Notion; MCP OAuth tokens for custom tools.
- **`claude bedrock setup`** — New interactive wizard introduced April 9 that walks through AWS credentials, region, profile, and model selection. Replaces a manual multi-file configuration process and is the first time Bedrock setup is parity-easy with native Anthropic API setup.
- **Per-Tool Connector Controls** — Cowork enterprise feature letting security admins specify which connectors and tools each user can invoke. Matches the granular-permission model in Claude Code's new policy controls and represents the operational primitive for tenant-isolation in shared Cowork installations.
- **OTLP endpoint** — OpenTelemetry Protocol endpoint accepted by Datadog, Grafana, New Relic, Honeycomb, and other observability platforms. Cowork's native OTLP support means enterprise admins can stream usage and cost telemetry into existing observability pipelines without custom adapters.

## Relevance to AgentNexLiFy

Three concrete shifts follow for the platform. First, the credential vault should replace any rolled-our-own per-tenant secret storage we currently use for OAuth-style integrations — let Anthropic own the vault for connector-based tools and treat it as a first-party security primitive rather than recreating it. Second, $0.08/hr active-session billing makes Managed Agents materially cheaper than self-hosted runtime for the cron-style ops automations on our roadmap (missed-call-text-back, appointment booker, auto-follow-up, doc drafter), and we should re-cost those workloads now that the public-beta number is fixed. Third, the OpenTelemetry support in Cowork is not for tenants but for our internal observability — if we run Cowork as part of our internal stack, OTLP into Datadog or Grafana eliminates the dashboard-bridge work and lets the same dashboards we already use for backend metrics absorb agent telemetry without code changes.
