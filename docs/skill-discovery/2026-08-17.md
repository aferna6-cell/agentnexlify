### 1. `dependabot-merge-runner`

**Trigger condition:** Morning digest or manual review shows 3+ Dependabot PRs that have been open for 5+ days with no merge action.

**Steps it would automate:**
1. List all open PRs (`mcp__github__list_pull_requests`) filtered by author `dependabot[bot]`
2. For each, check CI status (`mcp__github__get_check_run` or `actions_list`) — skip any with failing checks
3. For PRs with CI green and no requested changes: merge via `mcp__github__merge_pull_request` (squash merge)

5. Log merged + skipped count to `ops/routines/logs/dependabot-merge-YYYY-MM-DD.md`

**Why no existing skill covers this:** `pr-backlog-triage` (proposed 2026-08-10) was broader (all PRs). This skill is narrower and directly executable — Dependabot PRs have a clear merge-safe heuristic (CI green + no review request) that a general triage skill cannot assume.

### 3. `orphaned-commit-recovery`

**Trigger condition:** `git log origin/main..HEAD` shows commits not in origin, OR nightly review fires "Structural Finding — orphaned commits", OR `git symbolic-ref HEAD` returns empty (detached HEAD).

**Steps it would automate:**
1. Run `git log origin/main..HEAD --oneline` to identify unsynced commits
2. If commits found: run `git status` to confirm no uncommitted changes
3. Check if current session is on a branch or detached HEAD (`git symbolic-ref HEAD`)
4. **If on a branch:** run `git push -u origin <branch> --force-with-lease`, then verify with `git log origin/<branch>..HEAD` (should be empty)
5. **If detached HEAD:** run `git checkout main && git pull origin main`, then cherry-pick or merge the orphaned commits onto main
6. Open a recovery PR if the commits contain substantive changes (not ops logs)
7. Log the recovery action to `ops/routines/logs/orphaned-commit-recovery-YYYY-MM-DD.md` with commit SHAs before/after

**Evidence:**
- 2026-08-07 incident: nightly committed `cbbaae5` + `7dff08b` on detached HEAD, orphaned. 2026-08-08 nightly had to re-discover and re-apply both fixes (re-documented in `nightly-commit-review-2026-08-08.md`)
- 2026-08-11: `926d798` nightly review opened on detached HEAD again (same failure mode). Detached HEAD guard fired and was added to skill to prevent future occurrences
- 2026-08-16 nightly (`ddd8e77`): Structural Finding — 6 commits (subconscious runs 103+104, morning digests, nightly reviews from 2026-08-14/15) existed in local HEAD but not in `origin/main`. The nightly log said "Human should run `git branch recover-orphans 00940d9`"
- 2026-08-17 subconscious (`2eff207`): recovered and pushed those 6 orphaned commits as part of the `git push` fix

**Frequency:** 3 occurrences of orphaned commits in 10 days (2026-08-07, 2026-08-11, 2026-08-16). Each required at minimum a human investigation step or a full subconscious run to recover.

**Note on partial mitigation:** The `git push origin HEAD` addition to subconscious SKILL.md Phase 8 (implemented 2026-08-17) reduces future orphaning from subconscious runs. But nightly-commit-review and other scheduled tasks still lack a push step, meaning the pattern will recur whenever those sessions commit without pushing.

**Estimated time saved:** 15-20 min per occurrence. At 3/10-day rate = ~45-60 min per 10 days. The skill pays off in a single use.
