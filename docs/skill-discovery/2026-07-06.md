### 1. `nightly-step-author`

**Trigger condition:** Subconscious winning-concept.md identifies a new operational check that should run nightly AND tags it AUTONOMOUS-EXECUTABLE. Also triggered when user says "add a new monitoring step to nightly", "add a check to the nightly review", or "teach nightly to watch for X".

**Steps it would automate:**

1. Read `.claude/skills/nightly-commit-review/SKILL.md` — locate the last numbered 9x step and step 10
2. Determine the next step label (9 → 9A → 9B → 9C → 9D, etc.)
3. Identify the bash check command for the condition (existence check, log tail, grep, etc.)
4. Write the new step block using the canonical template:
   - `Nx. (<Name>) <one-line description of what it checks>:`
   - Bash command block
   - `If <CONDITION>:` branch with action (write file, create GH issue, commit)
   - `If <NOT CONDITION>:` branch with skip log (e.g., "present — monitoring active — skip")
5. If the action involves creating a GH issue: add deduplication guard (search for open issue with label before creating)
6. Insert the new block between the last 9x step and step 10 (never after step 10)
7. Verify the SKILL.md still parses correctly (no broken step numbering, no orphaned code blocks)
8. Commit: `subconscious: run N — [brief description of new step]` using the standard commit format

**Evidence (both occurrences this week):**

Block structure: `ls ops/monitoring/healthz-alert.sh 2>/dev/null || echo "MISSING"` → if MISSING write from embedded content → commit → open GH issue. If EXISTS → skip log.
- `19682fc` (2026-07-06): Run 80 executed run 80's own winning concept — added Step 9C to nightly SKILL.md (brain connector failure detection). Block structure: `tail -20 brain/INGESTION-LOG.md` → count consecutive failures → if ≥3, search GH issue by label → if no open issue, create → skip log if found.
- Both were inserted between 9B and step 10, both followed the same conditional structure, both had deduplication logic.
- Prior: Step 9A (moratorium escalation) was added in an earlier subconscious run — same class, same authoring challenge.

**Estimated time saved:** 20–30 min per new step. The nightly SKILL.md is 220 lines with intricate step numbering. Finding the right insertion point, understanding the step template, writing correct dedup logic, and getting the commit message format right currently requires reading the full SKILL.md plus several prior winning-concept.md files for context. A skill reduces this to a 5-min guided insertion.

### 2. `ops-dedup-issue-create`

**Trigger condition:** Any autonomous action needs to create a GitHub issue where duplicate creation would be noisy (recurring operational checks, mandate escalations, human-action reminders). Triggered by phrases like "file a GH issue if none exists", "escalate to a ticket (no duplicates)", "create issue once", or when building a new nightly step that includes issue creation.

**Steps it would automate:**

1. Choose a unique label to use as the dedup key (e.g., `brain-connector-failure`, `healthz-missing`, `moratorium-overdue`)
2. Build the search query: `repo:aferna6-cell/agentnexlify label:<dedup-label> state:open`
3. Run `mcp__github__search_issues` with the query
4. If results found → log "already escalated (issue #N) — skipping creation" and stop
5. If no results → assemble issue body using the canonical structure:
   - `## Impact` — what breaks / what is stale
   - `## Fix (<N> min)` — numbered steps for the human to follow
   - `## Steps` — optional detail
6. Call `mcp__github__issue_write` with title, body, labels array (must include dedup label + `human-action-required`)
7. Log "GH issue #N created for <condition>"

**Evidence:**

- Step 9A (moratorium escalation) in nightly SKILL.md: searches for open issues, creates if none found
- Step 9C (brain connector check) added 2026-07-06: searches `label:brain-connector-failure state:open` before creating
- GH #394 (brain connector credentials, 2026-07-05): body uses ## Impact / ## Fix / ## Steps structure
- GH #393 (healthz-alert.sh P0, 2026-07-05): same structure
- The pattern was reinvented independently for Step 9A and Step 9C — canonical dedup logic should be extracted once

**Estimated time saved:** 10–15 min per occurrence. The GitHub MCP search query syntax, the "search before create" pattern, and the issue body template each require 5+ min to get right from scratch. With a skill, this becomes a 2-min parameterized invocation.

### 3. `stale-path-guard`

**Trigger condition:** Before executing any mandate that references a specific file path (e.g., "fix `backend/services/zapier_auth.py`"), run a path-existence check to verify the assumption. Also triggered when subconscious produces a winning concept that names a specific file as the fix target.

**Steps it would automate:**

1. Extract all file paths named in the mandate/winning-concept (grep for `backend/`, `frontend/`, `.claude/`, `scripts/`)
2. For each path: run `ls <path> 2>/dev/null || echo "NOT FOUND"`
3. For missing paths: grep for the symbol/entity mentioned to find the actual location (`grep -rn "<function_name>" backend/ --include="*.py" -l`)
4. If the actual location differs from the mandate's assumption: append a corrective note to `subconscious/state/memory.jsonl` before executing
5. Resume execution with the verified path

**Evidence:**

- `a170595` (2026-07-02, nightly): Nightly caught that subconscious runs 75–76 were tracking `backend/services/zapier_auth.py` (doesn't exist). The function `_get_api_key_client` is in `backend/routers/zapier.py`. Subconscious spent 2 full runs (75 + 76) trying to fix a file that didn't exist at the assumed path. GH #107 was already closed 19 days before run 75. Root cause: `zapier_file_found: false` false-negative from wrong path assumption → ghost tracking for 2+ cycles.
- kb-autopopulate was broken for 53 days in part because the DISCOVER_PROMPT contained a false instruction ("NEVER use WebFetch") — a stale assumption in the script's embedded content that no check was verifying.

**Estimated time saved:** One stale-path assumption costs 1–2 full subconscious runs (~7 days of wall-clock delay before the ghost tracking is caught). Preventing it saves those cycles entirely. The guard is cheap (3 bash commands) relative to the cost of a ghost mandate.
