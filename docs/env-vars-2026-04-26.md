# New Environment Variables (2026-04-26)

Add these to `.env.example` and your local `.env` / Railway env config.

## Per-tenant rate limits (optional — defaults sane)

```
RATE_LIMIT_FREE_RPM=30
RATE_LIMIT_GROWTH_RPM=120
RATE_LIMIT_AUTOPILOT_RPM=240
RATE_LIMIT_PROFESSIONAL_RPM=480
RATE_LIMIT_ENTERPRISE_RPM=1200
```

> **UPDATE 2026-06-22 (repricing 2026-06-15):** `growth`/`autopilot`/`professional`/`enterprise`
> are now LEGACY/grandfathered tiers. Current paid plans are `chatbot` ($19.99) and
> `agent_os` ($99.99). `backend/middleware/rate_limit.py::_env_rpm` reads
> `RATE_LIMIT_<TIER>_RPM` for ANY tier dynamically, but `_TIER_DEFAULTS` has no entry
> for `chatbot`/`agent_os` — so unless you set `RATE_LIMIT_CHATBOT_RPM` and
> `RATE_LIMIT_AGENT_OS_RPM`, both current plans fall back to the free-tier 30 rpm cap.
> Set these for current deploys:
> ```
> RATE_LIMIT_CHATBOT_RPM=120
> RATE_LIMIT_AGENT_OS_RPM=480
> ```

Used by `backend/middleware/rate_limit.py`. Caps `/api/v1/widget/chat` RPM per
tenant based on plan tier. If unset, defaults above apply.

## Sentry MCP (optional — local dev only)

```
SENTRY_AUTH_TOKEN=<your-sentry-personal-access-token>
SENTRY_HOST=sentry.io
```

Used by `.mcp.json` `sentry` entry. Lets Claude Code query Sentry errors via
MCP. Only needed if you want in-session Sentry queries. Not required for prod.
